# 升级、备份与恢复

## 升级前

1. 停止 Gofi，避免 SQLite 和上传会话在备份过程中继续变化。
2. 备份整个工作目录，而不是只备份 `storage/`。
3. 保存当前二进制或镜像标签，记录当前版本。

本地部署可以执行：

```bash
sh scripts/backup.sh /path/to/gofi-data /safe/path/gofi-backup.tar.gz
```

Docker 部署应先停止容器，再备份挂载到 `/app` 的卷。备份必须包含：

- `gofi.db`
- `.gofi-jwt-secret`
- `storage/`
- `.gofi-uploads/` 中尚未完成的上传会话

## 执行升级

替换二进制或镜像后，使用原工作目录启动。Gofi 会在显式启动阶段检查并升级数据库 schema。数据库版本高于当前程序支持版本时，程序会拒绝启动，避免旧程序破坏新数据。

旧 MD5 密码不会在启动时批量重写；对应账号成功登录后会自动迁移为 bcrypt。

## 验证

升级后至少检查：

```bash
curl --fail http://127.0.0.1:8080/api/configuration
```

随后验证登录、目录浏览、下载和一次小文件上传。尚未完成的分片上传会从磁盘会话继续。

## 回滚与恢复

1. 停止当前 Gofi。
2. 将当前数据目录移到隔离位置，不要直接覆盖。
3. 解压升级前备份，恢复原二进制或镜像。
4. 使用恢复后的完整工作目录启动并验证配置接口。

不要只回滚数据库而保留新版本写入后的存储目录，也不要从其他实例复制 `.gofi-jwt-secret`。恢复后的密钥必须与备份数据库配套。
