# Gofi 重构路线图

本路线图以里程碑记录重构进度。每个里程碑都必须满足退出条件后才能标记完成；新增 Bug 和功能请求应归入相应里程碑，而不是打断整体顺序。

## 状态定义

- `Planned`：已定义，尚未开始。
- `Active`：当前正在推进。
- `Blocked`：存在明确外部阻塞。
- `Complete`：所有退出条件满足。

## 总览

## M1 核心重构

> M1 已完成本地实现与验收。按维护者要求，本次只创建本地提交，不推送远端；GitHub Actions 和 linux/arm64 结果仍归入 M4 发布验收。

### 范围

#### 安全与正确性

- 定义游客、登录用户和管理员的权限矩阵。
- 引入集中式逻辑路径和值对象。
- 修复路径穿越、相似前缀和符号链接边界。
- 替换 MD5 密码散列，移除固定默认密钥和默认管理员密码。
- 统一认证失败、权限不足和资源不存在的 HTTP 语义。
- 复核 CORS、CSRF、代理 IP 和登录限流。
- 为关键边界增加集成测试。

#### 后端边界

- 建立显式应用启动和依赖装配。
- 将 Controller 中的文件系统与数据库逻辑迁移到应用用例。
- 引入强类型错误和稳定 API 错误码。
- 将配置和数据库 schema 改为显式迁移。
- 统一日志和 Trace 字段。

#### 前端边界

- 建立 app、features、shared 目录边界。
- 集中管理认证会话和 API 错误。
- 拆分文件列表页面的查询、呈现与操作状态。
- 建立上传任务模型。
- 清除重构期日志和硬编码文案。
- 补充关键交互测试与响应式检查。

#### 审计候选

- 修复未登录请求返回 HTTP 200 的错误语义。
- 补齐后端中英文翻译键。
- 统一文件读取、下载和前端路由的权限策略。
- 让 `/api` 请求绕过静态资源中间件，移除误导日志。
- 缩减 Shiki 语言包和大型构建 chunk。
- 更新 Browserslist 数据，消除 Node.js 弃用警告。

### 退出条件

- 所有文件 API 都通过统一存储入口访问文件系统并执行后端权限策略。
- 路径和权限测试覆盖穿越、相似前缀、符号链接、允许及拒绝场景。
- 新安装不会生成公开已知凭据，旧 MD5 密码可安全迁移。
- 日志不会输出密码、Token 或敏感本地路径。
- HTTP handler 不直接依赖 `os`、`filepath` 或数据库 Engine。
- 核心用例可以在不启动 Gin 的情况下测试。
- 包初始化不创建数据库、不写文件、不同步业务数据。
- API 使用稳定错误码和对应的 4xx/5xx HTTP 状态。
- HTTP 客户端不直接决定页面跳转或重复显示 Toast。
- 文件列表、文件查看器和上传流程各自具有清晰边界。
- 主要用户流程具有自动化测试。
- 中英文界面没有已知硬编码遗漏。
- 前端生产构建不再打包全部 Shiki 语言和主题。
- M1 范围内的构建、静态检查、单元测试、集成测试和 Docker 冒烟全部通过。

## M2 文件管理闭环

> M2 已完成。大文件使用磁盘持久化会话，支持续传、分片与整文件 SHA-256；文件操作和批量结果均通过统一路径与权限边界。

### 范围

- 可靠的普通与分片上传。
- 断点恢复、哈希校验、取消和过期清理。
- 新建目录、重命名、复制和移动。
- 批量选择与批量操作。
- 明确覆盖、冲突和部分失败语义。

### 退出条件

- 上传可在中断后继续，并能检测内容损坏。
- 所有写操作使用统一权限和路径策略。
- 失败不会留下对用户可见的半成品文件。
- 前后端对冲突和部分失败使用一致契约。

## M3 搜索与分享

> M3 已完成。SQLite 索引支持重建、增量刷新和容量上限；分享令牌仅存哈希，支持过期、撤销和目录子路径隔离。

### 范围

- SQLite 文件索引和后台扫描。
- 文件变化后的增量更新。
- 名称、路径和可选文本内容搜索。
- 可撤销、可过期的分享链接。
- 分享范围与游客权限整合。

### 退出条件

- 不启用索引时不影响基础文件浏览。
- 索引可重建，损坏后不会影响用户文件。
- 分享链接无法越过既定文件范围和过期时间。
- 搜索与分享均有容量和权限测试。

## M4 稳定版发布

> M4 的代码、迁移、文档、可复现构建、备份演练和 linux/amd64 容器验收已完成。当前旧版 Docker/QEMU 在运行 arm64 Go 工具时崩溃，且按维护者要求不推送远端，无法取得 GitHub Runner 结果，因此里程碑保持 Blocked，不伪造多架构通过。

### 范围

- 数据库、配置和密码迁移验证。
- Linux amd64/arm64 产物与 Docker 镜像。
- 升级、回滚、备份和恢复文档。
- 安全配置检查和发布清单。
- 清理过时分支、文档与兼容代码。

### 退出条件

- 从最后一个稳定版本升级有自动化或书面验证记录。
- 发布产物可复现并带校验文件。
- 快速开始、配置、FAQ 和贡献文档与实际行为一致。
- 没有未说明的高严重度已知问题。

## 里程碑维护规则

1. 一个时间点只允许一个主里程碑处于 `Active`。
2. 修复当前里程碑发现的回归，不顺手重构无关模块。
3. 新需求先写问题、复现或用户场景，再决定所属里程碑。
4. 每个完成项必须有测试、验证命令或人工验收记录。
5. 里程碑状态变化必须在本文件的提交中记录。
6. 原始审计输出、临时假设和 Issue 草稿属于本地维护资料，不提交到仓库。

## 公开文档与本地记录

应提交到 Git 的内容：

- 对用户和贡献者有效的产品边界。
- 当前功能状态和已知限制。
- 架构决策、里程碑与验收标准。
- 可复现的 Bug、测试和迁移说明。

不应提交到 Git 的内容：

- 本机绝对路径、Token、Cookie、账号和环境快照。
- 未核实的安全判断或针对个人的评论。
- 临时命令输出、原始扫描结果和对话记录。
- 尚未整理的 Issue 文案和个人推进日志。

本地维护资料统一放在被 `.gitignore` 忽略的 `.gofi-work/` 目录中。
